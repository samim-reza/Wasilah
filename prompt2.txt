# QURAN.COM / QURAN FOUNDATION INTEGRATION — MANDATORY

The application should use the **official Quran.com / Quran Foundation ecosystem** as the primary source for Quran functionality rather than building an independent Quran content database from scratch.

Quran.com maintains open-source software projects, including its web frontend and mobile applications. The official Quran Foundation developer platform provides APIs for Quran content and user-related Quran features.

Official resources:

* Quran.com Developer Platform
* Quran Foundation API
* Quran Foundation JavaScript/TypeScript SDK
* Official Quran.com GitHub repositories

Use the official APIs and official open-source repositories as architectural and implementation references.

---

## 1. PRIMARY QURAN DATA SOURCE

Use **Quran Foundation APIs** for Quran content.

Do NOT scrape Quran.com.

Do NOT download or copy the Quran.com website.

Do NOT create a manually maintained duplicate Quran dataset unless explicitly required and legally permitted.

The application should retrieve appropriate content through the official API.

Content may include:

* Quran chapters
* Quran verses
* translations
* tafsir
* word-by-word translations where available
* word-by-word transliteration where available
* recitations
* chapter recitations
* Mushaf/page information where available
* Juz
* Hizb
* Ruku
* Manzil
* Quran search
* other officially supported Quran content

Use the official API documentation to determine the correct endpoint and current API version.

---

# 2. USE THE OFFICIAL TYPESCRIPT SDK WHEN APPROPRIATE

Because this application uses TypeScript, prefer the official Quran Foundation JavaScript/TypeScript SDK where appropriate rather than manually duplicating API client logic.

Use the server-side SDK/backend integration for protected Content API requests.

Keep the Quran API implementation isolated:

```text
src/
  lib/
    quran/
      client/
      config/
      types/
```

or, if feature-based organization is preferable:

```text
src/
  features/
    quran/
      api/
      services/
      hooks/
      types/
      components/
```

Do not allow React components to directly construct Quran API requests.

Preferred architecture:

```text
Quran UI
    ↓
React Hook
    ↓
Quran Service
    ↓
Quran API Client / SDK
    ↓
Quran Foundation API
```

---

# 3. API CREDENTIAL SECURITY

Quran Foundation Content API credentials must NOT be embedded in the mobile application.

The Content API uses backend authentication.

Keep sensitive credentials server-side.

Preferred architecture:

```text
React Native / Expo
        ↓
Our backend / Supabase Edge Function
        ↓
Quran Foundation API
```

Never put:

```text
QF_CLIENT_SECRET
QF private credentials
server secrets
```

inside the Expo client bundle.

Use environment variables and server-side secrets.

Example:

```text
QF_CLIENT_ID=
QF_CLIENT_SECRET=
QF_ENV=
```

The exact environment variable names may be changed, but maintain one consistent naming convention.

# 6. QURAN CONTENT MUST REMAIN AUTHORITATIVE

Never modify Quran text.

Never "correct" Quran text manually inside application code.

Never generate Quran text using an LLM.

Never use AI-generated Quran verses.

Never silently substitute an unofficial Quran dataset when official content is available.

If content is displayed from Quran Foundation, preserve the content and context supplied by the source.

Translations must be treated separately from the Quran's Arabic text.

The architecture should support multiple translation editions.

Example:

```text

    +

    +
Translation B
    +
Translation C
```

Do not hardcode one translation into the reader.

The user should eventually be able to select:

```text

    ↓
English
Bengali
Urdu
Hindi
etc.
```

subject to the availability and licensing of each translation.

Record the translation edition/source.

# 13. CACHING AND OFFLINE STORAGE

Do not assume that arbitrary Quran API data can be cached indefinitely.

Follow the current Quran Foundation Developer Terms.

The implementation must respect the applicable content caching/storage limits.

If using Content Sync APIs or another officially supported offline mechanism, implement the required synchronization behavior.

For content that is not eligible for long-term storage:

```text
API
 ↓
short-lived cache
 ↓
application
```

For approved Content Sync resources:

```text
Content Sync
 ↓
local storage
 ↓
periodic synchronization
 ↓
apply updates
```

Do not create an unrestricted offline Quran mirror without verifying that the specific content and API path permit it.


